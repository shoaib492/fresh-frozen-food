ROLE

You are a senior full-stack developer and premium brand designer. Build a

complete, production-ready, full-stack website for a high-end, premium

cloud kitchen (delivery-only restaurant brand), using its REAL data —

not placeholder content. This is a professional, luxury food brand —

the website must feel as premium and polished as a fine-dining

restaurant's site, not a generic food-delivery template.

Add payment options at checkout (Razorpay or Cash on Delivery) and store payment status with each order.



Send an SMS or WhatsApp notification with the order number and ETA after checkout completes.



Add SEO enhancements like structured data for menu items and richer OG tags for better social sharing

Add whatsapp button .







STEP 1 — EXTRACT REAL BUSINESS DATA

Before writing any code, pull the following from the links above:

- Exact business name, cuisine/category, phone number, email, delivery

hours/timings, delivery area/city (cloud kitchens usually don't have

dine-in, so treat "hours" as order-accepting hours)

- 5–8 real Google reviews (reviewer name, rating, short real quote) —

prioritize ones mentioning specific dishes, packaging, or quality

- Logo — use their real logo from Google/Instagram profile photo if

visible; otherwise recreate a clean vector version matching their

existing mark and style

- Brand color palette — identify the 2–3 dominant colors actually used

across their Instagram grid/highlights/packaging photos and use ONLY

this palette (typically deep/moody tones — charcoal, black, deep

green, burgundy, or gold-on-cream for premium food brands) across the

entire site

- Real photos from Instagram — actual dish photography, plating,

packaging, kitchen/chef shots, ingredients — use these as real images

throughout, never stock food photography

- Their real menu — scan Instagram captions/highlights and the Google

Business profile/menu link for actual dish names, descriptions, and

prices; organize into real categories used by this business (e.g.

Starters, Signature Mains, Chef's Specials, Desserts, Combos/Meal

Boxes); if exact prices aren't visible, write a believable price range

matching their premium positioning — never generic "Dish 1, Dish 2"

- Chef/founder name and story if mentioned anywhere on Instagram/Google

— premium food brands are often built around a chef's story, use it

if available

- Embed their real Google Maps location (for the kitchen address /

delivery-from location — interactive embed, not static image)



STEP 2 — BRAND MATCHING RULE

The entire site must feel like it belongs to THIS exact brand:

- Business name large and prominent in the header/hero

- Typography, imagery, and mood must reflect fine-dining-level

positioning — moody, editorial food photography treatment, not bright

cheerful fast-food styling

- Match their real colors and packaging aesthetic exactly — if their

brand uses black-and-gold, use black-and-gold; if it's minimal

cream-and-sage, use that — never default to red/yellow "generic food

app" colors unless that is genuinely their brand



STEP 3 — DESIGN DIRECTION (CRITICAL — must NOT look AI-generated or templated)

- No generic "food delivery app" layout — avoid the overused

bright-hero + emoji-icon-grid + rounded-cartoon-cards look completely

- Use a fine-dining editorial layout: large full-bleed dish photography,

generous dark or muted whitespace, elegant serif headlines paired with

a refined modern sans body font (not default system fonts), subtle

scroll-reveal animations, cinematic full-width image breaks between

sections

- Reference the visual language of premium restaurant/chef-brand

websites and high-end packaged food brands — think a Michelin-adjacent

restaurant site or a premium D2C gourmet brand — not Swiggy/Zomato

style UI

- Sticky navbar with a refined transition on scroll, tasteful hover

states on menu items (subtle zoom/reveal on dish images), smooth

fade/slide-in animations as sections enter view

- Every section must feel custom-built for this specific brand — never

reused from a generic food template



REQUIRED SECTIONS

1. Hero — business name large, tagline, cinematic dish photography or

short food video loop background, primary CTA ("Order Now" /

"View Menu")

2. About / Story — the brand's real story, chef/founder background if

available, what makes their food/positioning premium

3. Signature Dishes — a curated highlight of 3–5 hero dishes with large

photography and short elegant descriptions

4. Full Menu — organized by real categories, each item with name, short

description, and price, filterable if the menu is long (veg/non-veg,

category tabs)

5. Gallery — real Instagram food/kitchen photography in an elegant grid

6. Testimonials — real Google reviews, styled elegantly with ratings

7. Delivery Info — delivery area/city, hours, estimated delivery time,

minimum order if applicable

8. Order Now — a REAL, working ordering flow (see backend requirements

below), not just a "call us" button

9. Location — embedded Google Map (kitchen location / delivery zone)

10. Footer — logo, contact info, social links, hours, quick links



FULL-STACK / BACKEND REQUIREMENTS

- A genuine ordering system:

- Browse menu by category → add items to a cart → adjust quantity →

view running total → checkout with name, phone, delivery address,

and any notes (e.g. spice level, allergies)

- Order saves to a real database with a unique order number and

status (received/preparing/out for delivery/delivered)

- Order summary/confirmation screen shown after checkout with the

order number and estimated delivery time

- Cart state persists while browsing (so items aren't lost on

navigation)

- Admin dashboard (simple protected route) to view all incoming orders,

see item details, update order status, and view daily order volume

- Full client + server-side validation (valid phone number, required

delivery address, no empty cart at checkout, etc.)

- Proper loading, empty ("Your cart is empty"), and error states

everywhere — nothing should ever show a blank or broken screen

- Fully mobile responsive (test at 375px, 768px, 1024px, 1440px+) — most

real customers will order from their phone, so the mobile menu-

browsing and checkout flow must be flawless and fast

- Fast image loading (lazy load, optimized sizes, no layout shift while

images load — this matters a lot for a photography-heavy food site)

- Basic SEO: meta title/description using the real business name and

cuisine/city, OG tags (important for social sharing of food photos),

favicon from the logo



CODE QUALITY RULES

- Clean, modular, well-commented code — zero console errors

- Reusable components (menu item card, cart line item, category tab,

testimonial card) instead of repeated inline styles

- No "Lorem ipsum," no generic dish names like "Dish 1"/"Item A," no

broken links — every piece of content must be real or realistically

written for this specific brand

- Test the full order flow end-to-end (browse → add to cart → checkout

→ confirmation → appears in admin view) before considering the build

done

- Treat this as a real, professional client delivery — no bugs, no

half-working features, this brand's whole identity is being "premium,"

so the execution has to match that standard exactly



FINAL CHECK BEFORE FINISHING

- Does the homepage make it obvious within 2 seconds which real cloud

kitchen brand this is, and does it feel premium/high-end rather than

like a generic food delivery app?

- Do the menu items, descriptions, and prices feel like they belong to

a real, currently-operating premium kitchen rather than a template?

- Can a real customer actually place a full order from their phone,

start to finish, without errors?

- Is every image real dish/kitchen photography from their Instagram

rather than stock or AI-generated food images?

- Does the overall mood (colors, fonts, photography treatment,

whitespace) feel like a $50,000 premium brand site, not a $50 template?
